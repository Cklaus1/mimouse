# Lessons

- The capture task reads `CaptureRequest`s only after `InputCapture::new` returns; while a portal dialog waits, anything that expects a reply (e.g. `Focus`) hangs and fires late. Gate such requests in the service on `capture_status`/`capture_awaiting` (fixed for `cli focus` in 10fffe9).
- A megapc deploy that prints a `Get-FileHash` read error means Defender quarantined the exe: check `Get-MpThreatDetection` before suspecting the build. Test candidate exes by copying them to a scratch folder (write scan) and running `--version` (execution scan); never add exclusions (owner decision 2026-10-14).
- Agent briefs must quote the spec's latest `[REVISED]` text, not the integrator's memory of the item (K4 brief asked for routing that A-arch-3 REVISED had dropped).
- Before a cursor-moving smoke on megapc, check its interactive idle time (`/tmp/mmsmoke/mmidle.ps1` via `mmrun.ps1`). On 2026-10-14 16:16 someone was using it (idle 1.2 s): their own Ctrl double-taps and edge pushes mixed into the smoke log and looked like a release/re-enter regression. With a person present, smoke only non-cursor paths (revocation, clipboard, cli).
- A test failing only in parallel runs: read the panic line before calling it timing. The G2 "flaky" listen test panicked at `expect("listener")`: tests picked a UDP port by binding :0 and dropping it, and a sibling test's ephemeral UDP socket took it before the listener bound. Use `MiMouseListener::on_free_port` (retries). TCP helpers are safe (tokio sets SO_REUSEADDR). Timing tests use `start_paused` (tokio `test-util` dev-dep), not real sleeps (approval.rs failed 1 in 20 under load).
